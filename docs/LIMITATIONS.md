# 已知限制与下一步

本文件描述能力边界，不把“复杂架构”当作完成证据。

- **首版是开发者预览。** 主要环境为 macOS，中文目录/界面，固定本机 UI 端口，部分旧深度控制入口仍依赖额外服务。首次公开的原生主页已做挂载和清理测试，尚无不同用户机器上的长期使用数据。
- **判断仍依赖模型与可得证据。** 独立复核是独立调用/材料检查，不保证来自不同模型，也不能保证消灭幻觉。无法访问、相互冲突或未实测的来源必须保持未证实。
- **试跑有闭集边界。** 不是任意 GitHub 仓库的自动部署器。依赖、平台、联网限制可能使试跑不可用；macOS 沙箱能力不可假定在 Windows/Linux 等价存在。
- **网络搜索可能离线。** DDG/Bing 的可达性、页面结构与目标站点反爬会改变采集效果。没有登录绕过或私有站点凭据自动授权。
- **本地保存不等于全程本地推理。** 启用订阅 Agent 后，选中的公开材料和问题会交给该服务。调用是否包含在套餐内取决于用户账户与服务条款。
- **不是多租户服务。** 固定兼容 requester、回环服务与本机文件权限是当前边界。不要公网部署；也不要把同一 Vault 同时交给多个未协调的后端。
- **周月整理仍需长期验证。** 有合成规模、稳定主题和修订回归，尚不等于已证明一个自然月每天 10 条的可靠无人值守。知识完整度也没有可客观保证的百分比。
- **自迭代目前以知识和运行恢复为主。** 可修订结论、保留历史、受限恢复；不会自主修改系统代码并发布，也未实现可随意接入的商业模块体系。
- **没有对外 SLA。** 已知阻塞应如实暴露；没有“任何输入都一定得到结论”或固定交付速度承诺。

优先改进：新机器完整研究验收 → 主工作台进一步收敛旧入口 → 持续真实输入衡量结论质量、人工介入率与恢复可靠性 → 稳定 Agent 消费契约。扩展业务模块应建立在这些证据之上。
